用于修复明确的问题现象、报错、测试失败或回归。

执行流程：
1. 明确复现条件、影响范围和期望行为；信息不足时只问必要问题。
2. 定位相关实现和测试，优先写最小失败测试或复现命令。
3. 先确认失败，再做最小修复；不要顺手重构无关代码。
4. 运行目标测试、相关测试和 `pnpm build`。
5. 汇报根因、修改点、验证结果和仍需人工确认的内容。

约束：不盲猜；不绕过测试、类型或权限检查；不自动提交。
