# 代码审查

对当前分支的改动进行代码审查。

## 使用方式

`/review`

## 执行步骤

1. 运行 `git diff` 查看当前未提交的改动
2. 如果没有未提交改动，运行 `git log --oneline -5` 查看最近提交，对最新提交做 review
3. 逐文件审查，关注以下方面：
   - **正确性**：逻辑是否正确，边界条件是否处理
   - **安全性**：是否有注入、路径遍历等风险
   - **一致性**：是否符合项目现有风格
   - **性能**：是否有明显性能问题（大文件全量读取、同步阻塞等）
   - **错误处理**：异常路径是否覆盖
   - **类型安全**：TypeScript 类型是否准确，有无 any 滥用
4. 运行 `pnpm build` 确认编译通过
5. 运行 `pnpm test` 确认测试通过
6. 输出审查结果，按严重程度分级：
   - 🔴 必须修复（bug、安全问题）
   - 🟡 建议修复（代码质量、可维护性）
   - 🟢 可选优化（风格、命名）

## 约束

- 只评价改动的代码，不对未改动代码提意见
- 给出具体的文件和行号
- 每条意见附带修复建议
