# ds-code PRD（产品需求文档）

## 1. 文档信息

| 项目 | 内容 |
|------|------|
| 产品名称 | ds-code |
| 包名 | `@mrdistore/ds-code` |
| 当前版本 | 1.0.3 |
| 产品形态 | 终端交互式 AI 编程助手 CLI |
| 目标平台 | Node.js >= 20，Windows/macOS/Linux 终端环境 |
| 文档状态 | 基于当前实现整理 |

## 2. 产品背景

开发者在日常编码中需要频繁完成代码阅读、文件修改、命令执行、错误排查、测试补充和项目状态检查。通用网页 AI 对话工具无法直接访问本地项目，也无法安全地执行本地工具链。

ds-code 旨在提供一个运行在用户终端内的 AI 编程助手，使用 DeepSeek、OpenAI 或 OpenAI-compatible API，通过工具调用直接理解和修改当前项目，并以权限确认机制控制写入和命令执行风险。

## 3. 产品目标

### 3.1 核心目标

1. 让用户可以在终端中用自然语言完成软件工程任务。
2. 让 AI 能安全读取、搜索、编辑项目文件并执行必要命令。
3. 提供类似 Claude Code 的交互体验，包括流式输出、工具调用展示、权限确认、上下文管理和会话恢复。
4. 支持 DeepSeek、OpenAI 和 OpenAI-compatible 中转站，降低模型供应商绑定。

### 3.2 成功指标

| 指标 | 目标 |
|------|------|
| 首次启动体验 | 1 秒内显示欢迎信息和输入提示 |
| 普通对话响应 | 用户发送后尽快看到流式输出，而非等待完整响应 |
| 工具调用可靠性 | 工具参数错误可反馈给模型重试，不导致 CLI 崩溃 |
| 权限安全 | 写文件和执行命令默认需要确认，危险命令直接拒绝 |
| 长对话稳定性 | 接近上下文上限时自动压缩，不因 token 超限直接失败 |
| 回归质量 | 核心模块具备单元测试，发布前 build/test 通过 |

## 4. 目标用户

### 4.1 主要用户

| 用户类型 | 需求 |
|----------|------|
| 独立开发者 | 快速修 bug、补测试、重构、生成代码 |
| 项目维护者 | 审查改动、理解代码、整理发布流程 |
| 使用 DeepSeek/OpenAI-compatible API 的开发者 | 用自己的 API key 获得本地 AI 编程助手体验 |
| 终端重度用户 | 不离开 shell 完成 AI 辅助开发 |

### 4.2 非目标用户

- 希望使用图形化 IDE 插件体验的用户。
- 不愿配置 API key 或不希望模型访问本地代码上下文的用户。
- 需要云端多人协作产品而非本地 CLI 的团队。

## 5. 使用场景

### 5.1 代码理解

用户在项目根目录启动 ds-code，询问某个模块如何工作。产品读取相关文件、搜索符号，并返回解释。

示例：

```bash
ds-code
> 解释 src/core/agent.ts 的工具调用流程
```

### 5.2 Bug 修复

用户描述错误现象，产品定位代码、补充复现测试、修改实现并运行测试。

```bash
ds-code "修复 /model 命令切换 reasoner 后仍传 tools 的问题"
```

### 5.3 文件编辑

用户要求新增工具或修改配置。产品先读取现有模式，再写入或编辑文件；执行写入前弹出权限确认。

### 5.4 命令执行

用户要求运行测试或构建。产品调用 bash 工具执行命令，并展示 stdout/stderr 与退出状态；危险命令直接拒绝。

### 5.5 长会话恢复

用户退出后再次进入，可以通过 `--resume` 或 `/resume` 恢复最近一次会话上下文。

## 6. 产品范围

### 6.1 当前版本范围

当前版本覆盖：

- 终端交互式对话。
- OpenAI-compatible 流式 API 调用。
- DeepSeek/OpenAI/custom provider 配置。
- 文件读取、写入、精确替换。
- 文件名搜索、内容搜索、目录列表。
- shell 命令执行。
- 权限确认与危险命令拒绝。
- 上下文压缩。
- 会话保存与恢复。
- Slash commands。
- 基础 Git 状态工具函数。

### 6.2 暂不包含

- 子 Agent 并行任务系统。
- 插件市场或外部插件加载。
- GUI/IDE 插件。
- 云端同步、多用户协作、团队权限管理。
- 内置代码索引数据库。

## 7. 功能需求

## 7.1 CLI 启动与配置

### FR-001 启动交互会话

用户可以运行 `ds-code` 启动交互式终端应用。

验收标准：

- 显示产品名、版本和输入提示。
- API key 缺失时给出明确错误提示。
- 默认工作目录为用户启动命令时的当前目录。

### FR-002 初始 prompt

用户可以通过位置参数传入初始任务。

```bash
ds-code "帮我解释这个项目结构"
```

验收标准：

- 启动后自动发送初始 prompt。
- 初始任务完成后进入交互模式。
- `--model`、`--provider`、`--base-url` 可与初始 prompt 同时使用。

### FR-003 配置来源

产品支持全局配置、项目配置、环境变量和 CLI 参数。

配置路径：

- 全局配置：`~/.ds-code/config.json`
- 项目配置：`.ds-code/settings.json`

验收标准：

- 项目配置覆盖全局配置。
- CLI 参数覆盖配置文件。
- `DEEPSEEK_API_KEY` 和 `OPENAI_API_KEY` 可作为 API key 来源。
- 缺少 API key 时不进入主界面，并提示配置方式。

## 7.2 模型与 API

### FR-004 DeepSeek 支持

产品默认支持 DeepSeek provider。

支持模型：

- `deepseek-v4-pro`
- `deepseek-v4-flash`
- `deepseek-reasoner`

验收标准：

- `pro`、`chat`、`deepseek-chat` 归一化为 `deepseek-v4-pro`。
- `flash` 归一化为 `deepseek-v4-flash`。
- `reasoner` 归一化为 `deepseek-reasoner`。
- reasoner 模型不传 tools，并正确处理 `reasoning_content`。

### FR-005 OpenAI/custom provider 支持

用户可以接入 OpenAI 或任意 OpenAI-compatible API。

验收标准：

- provider 为 `openai` 或 `custom` 时允许任意非空模型名。
- custom provider 允许设置 `baseUrl`。
- 请求使用 OpenAI Chat Completions 兼容格式。

### FR-006 流式输出

模型响应应以流式方式显示。

验收标准：

- 文本 chunk 增量渲染。
- 工具调用前已有文本不丢失。
- reasoning 内容不与普通 content 混淆。
- 网络或解析错误不导致 UI 崩溃。

## 7.3 对话与上下文

### FR-007 Agent 循环

产品应支持模型返回 tool calls，并将工具执行结果回传给模型继续推理。

验收标准：

- 纯文本响应直接返回给用户。
- 单次工具调用可执行并回传结果。
- 多轮工具调用可继续执行直到模型给出最终文本。
- 达到最大迭代次数时停止并提示。

### FR-008 上下文压缩

长对话接近上下文限制时，产品应自动压缩早期消息。

验收标准：

- token 使用量超过阈值时触发压缩。
- 压缩保留 system message 和最近消息。
- 压缩摘要保留关键决策、文件路径和任务上下文。
- 用户可通过 `/compact` 手动触发压缩。

### FR-009 会话持久化

产品应自动保存对话历史并支持恢复。

验收标准：

- 每轮对话后保存 session。
- `--resume` 启动时恢复最近会话。
- `/resume` 在交互中恢复最近会话。
- 无可恢复会话时给出友好提示。
- 损坏 session 文件不会导致程序崩溃。

## 7.4 工具系统

### FR-010 文件读取

AI 可以读取项目文件。

验收标准：

- 支持读取完整文件。
- 支持 offset/limit 行范围。
- 输出带行号，便于引用。
- 文件不存在时返回工具错误而非抛异常。

### FR-011 文件写入

AI 可以创建或覆盖文件，但需要权限确认。

验收标准：

- 写入前触发权限确认。
- 用户拒绝后文件不被写入。
- 写入失败返回 `isError: true` 工具结果。

### FR-012 精确编辑

AI 可以通过 old/new string 精确替换文件内容。

验收标准：

- old string 唯一匹配时替换成功。
- 匹配不到返回错误。
- 多处匹配且未指定 replace all 时返回错误。
- 支持 replace all。
- 编辑前触发权限确认。

### FR-013 搜索与目录列表

AI 可以搜索文件名、搜索文件内容和列目录。

验收标准：

- glob 支持 `**/*.ts` 等模式。
- grep 支持正则、大小写选项和上下文行。
- list dir 能区分文件和目录。
- 默认避免无意义扫描 `node_modules`。

### FR-014 Bash 命令执行

AI 可以在用户授权下执行 shell 命令。

验收标准：

- 执行前触发权限确认，白名单命令除外。
- 捕获 stdout、stderr 和 exit code。
- 支持 timeout。
- Ctrl+C 可中断执行。
- 危险命令直接拒绝，不弹确认。

### FR-015 工具注册与 schema

所有工具应通过统一 registry 注册并导出 function calling schema。

验收标准：

- 工具名称唯一。
- 参数 schema 可转换为 OpenAI tools 格式。
- 参数缺失或类型错误返回明确工具错误。
- 未知工具返回明确错误。

## 7.5 权限与安全

### FR-016 权限确认

写入和执行类操作必须由用户确认。

验收标准：

- 权限提示展示工具名和关键参数。
- 支持本次允许、始终允许、拒绝。
- 始终允许对后续同类操作生效。
- 拒绝后将错误结果回传给模型。

### FR-017 危险命令拦截

高风险 bash 命令应直接拒绝。

验收标准：

- 明显删除根目录、破坏系统或高风险命令不执行。
- 黑名单优先级高于白名单和 always allow。
- 用户看到明确拒绝原因。

## 7.6 终端交互体验

### FR-018 Slash commands

产品提供内置 slash commands。

| 命令 | 需求 |
|------|------|
| `/help` | 显示可用命令 |
| `/clear` | 清空 UI 消息并重置 Agent 上下文 |
| `/exit` | 退出程序 |
| `/model [name]` | 查看或切换模型 |
| `/status` | 显示 provider、模型、session、token、工具数 |
| `/tools` | 列出可用工具 |
| `/resume` | 恢复最近会话 |
| `/memory` | 显示 system prompt 摘要 |
| `/compact` | 手动压缩上下文 |
| `/cost` | 显示 token 估算 |
| `/doctor` | 检查运行环境 |
| `/version` | 显示版本 |

验收标准：

- slash command 不发送给模型。
- 未知命令给出提示。
- 命令输出不破坏当前对话 UI。

### FR-019 命令补全

输入 `/` 时显示命令候选。

验收标准：

- 根据前缀匹配命令。
- 支持方向键选择。
- 支持 Tab/Enter 填充命令。
- Esc 取消候选。

### FR-020 多行输入

用户可以输入多行文本。

验收标准：

- 单独一行 `"""` 进入多行模式。
- 再次输入单独一行 `"""` 提交多行内容。
- 多行模式中 Ctrl+C 取消当前输入。
- 空多行输入不发送。

### FR-021 中断行为

用户可以用 Ctrl+C 中断当前操作。

验收标准：

- API 请求中 Ctrl+C 取消请求。
- 流式输出中 Ctrl+C 停止输出并回到输入状态。
- bash 执行中 Ctrl+C 尝试终止子进程。
- 空闲状态 Ctrl+C 不直接误退出；Ctrl+D 退出。

## 8. 非功能需求

### 8.1 性能

| 项目 | 要求 |
|------|------|
| 启动速度 | 本地配置正常时 1 秒内进入可输入状态 |
| 流式响应 | 收到第一个 content chunk 后立即展示 |
| 工具搜索 | 常规项目中搜索应避免扫描大型依赖目录 |
| 上下文管理 | 压缩后继续保持可用上下文，避免 token 超限 |

### 8.2 可靠性

- API 网络错误、限流和服务端错误应按策略重试或友好提示。
- 工具执行失败不能导致 Agent 或 UI 崩溃。
- session 文件损坏时跳过并提示。
- 命令执行超时应终止并返回错误。

### 8.3 安全性

- 默认不自动执行写入和命令类操作。
- 权限确认必须展示用户可理解的操作摘要。
- 危险命令必须直接拒绝。
- API key 不应出现在普通输出、日志或工具结果中。
- 文件操作应限定在用户明确工作目录语境内，避免隐式破坏系统文件。

### 8.4 可维护性

- 使用 TypeScript 类型约束，不使用 `any`。
- 工具层以 `ToolResult` 表达可预期错误。
- 核心层使用 typed error class。
- named export，不使用 default export。
- 新工具、新命令、新配置项必须补充测试。

### 8.5 可移植性

- 支持 Windows/macOS/Linux。
- Shell 命令执行应兼容用户当前 shell 语义。
- 文件路径处理应兼容不同平台路径分隔符。

## 9. 数据与配置

### 9.1 配置数据

配置文件字段：

```json
{
  "provider": "deepseek",
  "apiKey": "sk-xxx",
  "baseUrl": "https://api.deepseek.com",
  "model": "deepseek-v4-pro",
  "maxTokens": 16384,
  "temperature": 0,
  "timeout": 60000,
  "permissions": {
    "allowedCommands": ["pnpm test", "pnpm build"]
  }
}
```

### 9.2 会话数据

会话保存内容：

- session id。
- 创建/更新时间。
- system/user/assistant/tool 消息历史。
- tool call 关联信息。
- reasoning content（如模型返回）。

### 9.3 不保存的数据

- 不应明文写入不必要的 API key 副本。
- 不保存用户未确认执行的命令结果。
- 不上传本地代码到除用户配置的模型 API 以外的服务。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 模型误调用工具 | 可能误读或误改文件 | 写入/执行权限确认，危险命令拒绝 |
| OpenAI-compatible API 行为差异 | 请求或流解析失败 | 保留 provider/custom 配置，错误结果清晰暴露 |
| 长上下文成本升高 | 延迟增加或超限 | token 估算与自动压缩 |
| 用户误选 always allow | 后续操作风险增加 | dangerous command 黑名单优先，提示展示关键参数 |
| Windows shell 差异 | 命令行为不一致 | 测试覆盖 Windows 环境，路径处理用 Node API |
| 文档和实现漂移 | 后续开发误判状态 | 以 `docs/PROJECT_PLAN.md` 和测试结果作为状态源，定期更新 |
